# Discoverability — crawlable pages, previews and the sitemap

Owner document for how this product is found and how it appears when somebody
shares a link. Gate 3 in [`public-release-roadmap.md`](public-release-roadmap.md)
owns the release decision; this document owns how it works.

---

## 1. The problem a hash route creates

`CLAUDE.md` fixes routing as one hash: `#/<slug>` is a scene, `#/organs` is the
explorer. That decision is right for the application and wrong for everything
outside it, because **a crawler is never sent a fragment**. To a search engine,
a link preview or a sitemap, all twenty models are one URL with one title.

The fix is not to change routing. It is to give the outside world what it can
actually read.

## 2. What the build emits

Generated by `scripts/site-plugin.js` from `src/catalog/` — nothing is
hand-maintained, so a new scene still means one manifest entry and no more:

| Output | Contents |
| --- | --- |
| `dist/s/<slug>/index.html` | One page per **public** scene: title, description, maturity, review state, the educational-model boundary, and a link into the model |
| `dist/sitemap.xml` | Site root plus every scene page. Emitted only with `VITE_SITE_URL` |
| `dist/robots.txt` | Allow-all plus the sitemap reference |
| `dist/index.html` | Canonical, Open Graph, Twitter and `WebSite` JSON-LD injected into the app shell |

The scene pages need no bundle, no fonts and no JavaScript. That makes them the
most robust WebGL-independent surface in the product: a reader with a browser
that cannot start a renderer can still learn what a model is about and what it
does not claim.

## 3. Rules the generator keeps

- **Prototype work is not published.** Only `PUBLIC_SCENES` get a page or a
  sitemap entry. A Prototype scene deliberately makes no numerical claim, and a
  search result is exactly where that caveat is lost. There is no `Disallow`
  rule for it either: robots.txt matches paths, so a rule for `#/lab` would look
  like protection and provide none.
- **No guessed canonical.** Without `VITE_SITE_URL` the pages are still built,
  but canonical and Open Graph URLs are omitted and the sitemap is skipped. A
  wrong canonical is worse than none — it tells a search engine the real page is
  somewhere that does not exist.
- **No image is advertised unless it exists.** A preview that cannot load its
  image renders a broken card. The build lists by name every scene missing
  `public/social/<slug>.png` instead of pointing at a file that is not there.
- **The structured data does not overclaim.** Each page is a
  `LearningResource`, not a `MedicalWebPage`, and its topic is a plain `Thing`
  rather than a `MedicalCondition`. Describing the product to a search engine
  as clinical reference material would assert an authority the model cards
  explicitly decline. Every page carries the disclaimer in both languages.
- **Catalogue text is escaped, in markup and in JSON-LD.** A `</script>` inside
  a title would otherwise terminate the structured-data block and the rest
  would be parsed as markup, so `<`, `>` and `&` are unicode-escaped there.

## 4. Configuration

| Variable | Effect when unset |
| --- | --- |
| `VITE_SITE_URL` | Pages are built; canonical/OG URLs omitted and no sitemap |

Set it to the deployment origin, with no trailing path unless the site is
served from a subpath (`https://example.org/lab`). Links from a scene page into
the app are relative (`../../#/<slug>`), so a subpath deployment works either
way.

## 5. Social cards — the part that is not done

Link previews want a 1200 × 630 raster. This repository cannot produce one: it
has no rasteriser, and adding one would break the single-dependency rule that
keeps the build honest (`three` and nothing else).

So the contract is explicit rather than silent. Drop `public/social/<slug>.png`
into the repository and the build advertises it — `og:image`, `twitter:image`
and `summary_large_image` all switch on for that scene. Until then the build
prints exactly which scenes are missing one, and the pages advertise no image at
all.

Producing those cards is a design task, and the obvious source is the product
itself: the reel export already renders a scene at an exact pixel size.

## 6. Checked in CI

- `tests/site-metadata.test.js` — the generator's output: escaping, canonical
  behaviour, sitemap contents, structured-data typing, and that no Lab scene is
  ever listed.
- `npm run verify:site` — that the build actually emitted it. A plugin that
  silently stops running is the failure nobody notices until a preview is blank
  weeks later.
