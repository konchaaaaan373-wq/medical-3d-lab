# 病態説明の引き渡し — 何を提供していて、何を提供していないか

*2026-09-11。ブランチ `claude/pathology-expansion`。*

10 の病態シーンが、同じ 1 つの契約の上で「臨床家向け」と「患者向け」の両方を
持つようになりました（うち 2 つ——胆道閉塞とアカラシア——はこのブランチで
新しく作ったモデルです）。この文書は **境界** のためにあります: UI を作る側
（Work）と、正常解剖を作る側（Claude②）が、ここから何を読めばよくて、何を
自分で決めなくてよいのか。

## 病態の歩き方は 3 種類あり、混ぜません

1. **severity 型** — 1 つの機序が進む。COPD・喘息・肺炎・肺塞栓症・肺水腫・
   門脈圧亢進症・肝腎症候群。軸 = どこまで進んだか。
2. **scenario 型** — **別々の機序を並べる**。腎濾過（`situation`）と
   胆道閉塞（`site`）。選択は `kind: 'choice'` の制御で、
   **機序を切り替える step は軸を動かしません**。
   `tests/pathology-guides.test.js` がこれを固定し、どの選択肢が機序でどれが
   ベースラインかは**モデルに問い合わせて**判定します（軸が何も動かさない
   選択肢がベースライン）。
3. **balance 型** — 釣り合いが見つかる過程そのものが主題。アカラシア。
   何も起きない → 溜まる → 溜まったものが仕事を引き継ぐ。

新しい病態を足すときは、疾患の機序に合った型を選んでください。
全部を 4 stage に揃える必要はありません（アカラシアは 5 stage です）。

## 目的としての患者説明と医学教育（2026-09-27）

臨床家向けと患者向けは、**1 つのモデルの 2 つの目的**として画面に出ます。
利用者の身分ではなく用途の名前です（「患者説明」「医学教育」。初心者／上級者は使わない）。

- **状態は 1 つ。** 3D・計算・数値は共有し、目的で変わるのは文言・ガイド・初期表示・
  操作の出し方だけ。`src/app/purposeController.js` は何も計算しません
- **アドレスが状態。** `#/<slug>?purpose=patient`（医学教育は既定でパラメータ無し）。
  切替・共有リンク・再読み込み・戻るが同じ経路を通り、モデルも視点も再読み込みしません
- **患者説明が出るモデルは 1 か所が決める。** `src/access/patientPurpose.js` の
  `patientExplanationAvailable`：公開・版固定の医学レビュー・`access.patient`・説明文の
  4 つが揃ったときだけ。ヘッダーの切替・`#/patient`・ランディング・一覧が全部ここを聞きます
- **医学教育で動かした条件は持ち込まない。** 患者説明へ切り替えると、モデルの操作値と
  比較表示は開始状態に戻り、通知が出ます。進行軸の位置（両方が話している段階）は残します
- **課金は開くかどうかだけを決める。** 権限の無い読者にも患者説明の目的は出ますが、
  説明本文は開かず、鍵とプランの画面を出します（`installAccess` の `requestOpen` 1 か所）

検証は `npm run verify:purpose`。残課題は `docs/follow-ups.md` の F-224〜F-231。

## 患者向けの文言（2026-09-27 に平易な日本語へ書き直し）

患者説明の日本語（`src/data/patientGuides.js` の `titleJa` / `bodyJa` / `lookJa`、29 本・197 段）は、
英語からの直訳調で、医療者でないと読めない言葉が多く残っていました（「臼蓋」「楔」「断端」
「間質」「換気」「系全体の圧」、症状の「〜が語られます」、「この絵に人はおらず」など）。
主張・確からしさ（certainty）・限界の注記は変えずに、次の決まりで書き直しています。

- **専門用語は日常語で言う。** 言い換えた語は戻さない（`tests/patient-plain-language.test.js`
  の置き換え済みリスト）
- **診察室で聞く名前は残し、最初に出るところで説明する。** 「空気の通り道（気道）」
  「肺の奥の小さな空気の袋（肺胞）」のように、日常語と名前を括弧で結ぶ（同テスト）
- **症状は「〜が見られます」「〜を感じることがあります」と書き、「人によって大きく異なります」を残す。**
  関連（associated）の段で因果を言い切らない
- **画面の限界は「この画面は〜を示していません／描かれていません」で言う。** 「絵」は使わない
- **1 文 1 つのこと。** ダッシュ（——）や入れ子の長文を使わない。長さの上限は
  `GUIDE_STEP_LIMITS`（題 30・本文 110・見る場所 90 字）のまま
- **説明の題は、#/patient に並ぶ「知りたいこと」なので問いの形にする**（例:「広がった心臓は、
  なぜ送り出す効率が落ちる？」）。題も本文と同じく、英語版が言う以上を言わない
- **英語版（主張の出典）より多くを言わない。** 分かりやすくするために具体名を足すと、それは新しい
  医学的主張になります。最初の書き直しで「多くは血のかたまり」「すい臓」「リンパ液」「暗い場所で」
  「高い血圧など」「黄色くなる」を足し、レビューで英語と突き合わせて外しました。足したいときは、
  先に英語版と医学レビューを通す
- **確からしさを動かさない。** "depends on" を「決まる」、"is described" を「見られます」、
  "can" を言い切りにしない。症状は「〜があると言われます」

書き直しは医学レビューを経ていません。英語の文言は今回触っていません（F-232）。

## Work へ — 外枠は触っていません

`main.js`・ルーティング・ローディング・リトライ・ナビゲーション・Neco 導線は
1 行も変えていません。変えたのは `src/app/App.js` に 3 つ足しただけです:

- `app.guideView` — カメラとラベル。**モデルは動きません。**
- `app.guideState` — モデル制御と比較表示。**カメラは動きません。**
- `app.related` — 公開ゲートを通ったリンク一覧。

**この 2 つを分けてあるのが要点です。** step は「同じ状態の別の絵」にも
「別の状態の同じ絵」にもなれて、外から見てどちらなのか分かります。

患者モードの見た目で 1 つだけ CSS を持ち込みました（Claude① の branch から
そのまま）: `#ui.is-patient-guide .controls .button-row { display: none }`。
薄くして残すと、説明を受けている人の前に使えないボタンの壁が並びます。
**逃げ道はパネル自身の × と Escape で、どちらもパネル上にあります。**

**リンク一覧をどこかに書き写さないでください。** `app.related` が唯一の
供給元で、リリースが閉じているシーンは `App.js` が落とします。2 つ目のコピーは
「TO BE UPDATED」へのリンクになります。

## Claude② へ — 正常解剖の使い方

**新しい 2 シーンは、あなたのジオメトリをそのまま使っています。**
`claude/organ-expansion-implementation-jsd7j6` から 3 ファイルを
`git show` で写しただけで、1 文字も変えていません:

- `src/scenes/hepatobiliary/organs/biliaryTree.js`
- `src/scenes/gastrointestinal/organs/esophagusParts.js`
- `src/scenes/shared/anatomy/tubeParts.js`

**structure ID がそのまま接続点です。** 胆道モデルが圧を解く区間の名前
（`common-bile-duct`、`cystic-duct`、`pancreatic-duct` …）は、あなたの
`index` の mesh 名そのものであり、`tests/biliary-obstruction-model.test.js` が
「モデルが名前を付けた区間は、アトラスが実際に描く構造である」を固定します。
ID を変えるときは、このテストが落ちます——それが意図した知らせ方です。

食道も同様で、病態側は**あなたの curve の上に 2 本目のチューブを載せている**
だけです。あなたの管は名前で切り分けられており、そのままです。疾患がアトラスを
描き直す権利はありません。

マージ時の注意は F-46 に書きました（3 ファイルは同一内容なので衝突しない
はずですが、`tubeParts.js` は双方が新規追加する形になります）。



病態側から正常解剖を指しています。いまは `breathing-lungs` を指しています
（このビルドに存在する正常肺だから）が、**名前で指せる肺のアトラスが来たら、
差し替えるのは 1 ファイルの 1 行です** — `src/data/copd.js` と
`src/data/asthma.js` の `RELATED.scenes[].slug`。`App.js` がゲートを見て
自動で落とすので、公開前に足しても壊れません。

**病態のジオメトリと正常解剖は別物として扱っています。** リンクに必ず付く
注記が「いずれも別々のモデルであり、1 つの肺の段階ではありません。ここで
計算した値は持ち込まれず、向こうの値もここへは入りません」で、
`tests/pathology-guides.test.js` がこの注記の存在を確かめます。同じ患者の肺が
変形したようには見せない、という約束です。

**臓器ジオメトリ自体は変えていません。** COPD の 12 単位肺も喘息の 255 枝も
そのままです。触ったのはカメラの寄り先（`getGuideFramings`）と、その
シーンが自分の描画について宣言する文章（`getVisualMapping`）だけです。

## Claude① へ — 契約はそのまま使いました

`guideContract.js`・`guideSession.js`・`PatientGuidePanel.js`・`features.js`・
`ModelScopePanel.js`・`access.css` は branch `claude/heart-anatomy-b7` から
**そのまま**取りました（`git show` で写しただけで、1 文字も変えていません）。
`App.js` と `installAccess.js` は該当箇所だけ移植です。マージのとき、これらの
多くは同じ内容どうしで衝突しません。

`framing.js` の `fitPoseToSafeArea` / `orbitLimitsForSubject` は**持ってきて、
戻しました**。ここでは 1 度も走らないからです——効くのは
`scene.getSubjectBounds()` を持つシーンだけで、このブランチにはそれを持つ
シーンがありません。コンソールの帯の問題は、寄り先を実測して解きました
（下）。そちらが解剖シーンと一緒に持ってくるのが筋です。

**衝突する見込みがあるのは 3 か所です:**

1. `src/data/patientGuides.js` — そちらは heart / ischaemia / amyloid を、
   こちらは呼吸器・肝・腎を編集しています。**同じオブジェクトリテラルの
   別の場所**なので、たいてい自動でつきます。
2. `src/components/PatientGuidePanel.js` — こちらが 2 つ足しました:
   `setModelState` コールバックと、`reset({progress, controls})`。後者が
   振る舞いの変更です（下）。
3. `src/access/installAccess.js` — `stateSnapshot` と `movedByGuide` の扱い。

**`reset()` の振る舞いを 1 つ変えました。** そちらの規則は「モデルがいまいる
位置を説明している step で開く」で、位置は進行軸だけで決まっていました。
呼吸器では **同じ軸位置にいる 2 つの step が別々の肺について語る**（正常な肺と、
気道を狭くした同じ肺）ので、軸だけでは後に書いたほうが選ばれます。そこで
制御も渡すようにしました: 画面の肺を説明している step があればそれを開き、
なければその軸位置の最初の step を開いて、**モデルをその step が言う状態に
します**。心臓のシーンは制御を渡さないので、これまでどおり動きます。

## 検証 — 実ブラウザで歩かせています

```bash
VITE_ALLOW_PREVIEW=1 npm run build
npm i --no-save playwright        # 依存には入れていません
npm run verify:patient -- --preview --scene copd --shots shots/
```

各 step を実際に押し、宣言どおりに**カメラが動いたか / モデルが動いたか /
動かないはずのものが動いていないか**を測り、その step が指している構造が
ヘッダとコンソールのあいだの帯に入っているかをアンカーの射影で確かめます。

**この工程だけで 10 件の欠陥が出ました。** 横隔膜・換気単位・コンソリデーション
領域・側副血行路・輸入細動脈のラベルがコンソールやヘッダの裏にあり、
「腎臓を 2 つ見比べてください」と言いながら 1 つしか描いていませんでした。
`npm test` には原理的に見えないものです。CI 化は F-43。
