# Verification lessons — 検証そのものが嘘をついた事例

この repo には**失敗モードの台帳が 3 つ**あります。それぞれ持ち場が違います。

| 台帳 | 何を持つか |
| --- | --- |
| [`architecture-rules.md`](architecture-rules.md) | **3D シーンの構造**が静かに壊れた事例 |
| [`organ-3d-playbook.md`](organ-3d-playbook.md) | **レンダリング**の失敗モード（UV 極・両面シェル・飽和…） |
| **この文書** | **検証そのもの**が嘘をついた事例。テスト・検証スクリプト・計測 |

この文書が扱うのは、製品のバグではなく**「緑だったのに何も測っていなかった」**です。
プロダクトのバグは直せば消えます。**測る側のバグは、直るまで他の全部の信号を殺します。**

---

## 使い方 — 自己改善ループ

**間違いを 1 つ見つけたら、直す PR の中で、この台帳に 1 項目足してから次へ行く。**
別 PR に回さないでください。回した教訓は書かれません（実測: この repo で
「あとで書く」と言った教訓のうち、書かれたものは 1 件もありません）。

ループは 5 手です。

1. **ガードを書く** — テスト・検証スクリプト・アサーション、何でも
2. **壊す** — 修正を戻す / 条件を反転する / 対象を改名する
3. **赤を確認する** — 赤くならないガードは**存在していません**（L-09）
4. **戻して緑を確認する**
5. **ここに 1 項目書く** — 症状・どう見つかったか・いま何が捕まえるか

3 が要です。この台帳の A 節 8 件は**全部 2〜3 でしか見つかっていません**。
1 件も、書いた時点では間違っていると分かりませんでした。

`npm run lessons` が台帳の側を守ります——各項目が 3 つの欄を持つこと、
**名指ししたガードが実在すること**（消えたら赤くなるので、教訓を書き直すか
ガードを戻すことになります）、そして**まだ人しか捕まえられない項目が何件あるか**。
`npm test` からも同じ検査が走ります。

### 書き方

```markdown
### L-NN 1 行で「何が嘘をついたか」

- **症状**: 緑だったのに何が起きていなかったか
- **どう見つかったか**: ミューテーション / レビュー / 実機 / 偶然
- **いま何が捕まえるか**: `path/to/guard.js` — どう捕まえるか。
  機械が捕まえられないなら **人だけ**
- **一般形**: 次に同じ形が出るのはどこか（任意）
```

番号は再採番しません。ファイル全体の最大値の次を取ってください。

## A. 検証コードが、測っているつもりのものとは別のものを見ていた

**A 節 9 件は、ミューテーション以外では見つかっていません**（L-18 だけはレビューです）。
どれも、
書いた時点では正しく見え、レビューを通り、緑でした。

### L-01 不在の主張が、空文字列に対して通った

- **症状**: `node.text` は Playwright の `ElementHandle` には無く `undefined`。
  全行が空になり、「この文言は出ていない」という主張が**何も読まないまま**通った。
- **どう見つかったか**: ミューテーション。消したはずの文言を戻しても緑のまま。
- **いま何が捕まえるか**: **人だけ**。`textContent` を使い、`nonEmpty()` で
  「何かを読めたこと」を先に主張する形にしたが、次に同じ形を書くのを止めるものは無い。
- **一般形**: **「無いこと」の主張は、必ず「有ること」の主張とセットで書く。**
  空集合に対しては、あらゆる否定が通ります。

### L-02 正規表現が、別の規則の本体を読んだ

- **症状**: `\n\.locked-copy \{` が、グループセレクタ
  `.locked-summary,\n.locked-copy {` の**2 行目**に一致し、そちらの本体を読んだ。
- **どう見つかったか**: ミューテーション。`.locked-copy` 側の値を変えても緑。
- **いま何が捕まえるか**: `scripts/lib/css.mjs` — そのクラス名を含む規則を
  **全部**集めて最後を採る（`rulesNaming` / `fontSizePx`）。セレクタ 1 本を
  錨にしない。`tests/css-reading.test.js` がグループ選択子の実例で固定します。
- **一般形**: CSS のセレクタは行頭に無いことがあります。**グループの 2 行目以降**が
  常に待ち伏せています。

### L-03 1 つの規則の中で、最初の宣言を読んだ

- **症状**: 同じ本体に `font-size` が 2 行あるとき、勝つのは**後**。最初を読むと
  「10px が残っている」と報告し続ける。
- **どう見つかったか**: わざと control case（前が 10px・後が 12px）を置いた。
- **いま何が捕まえるか**: `scripts/lib/css.mjs` — `declaration()` が最後を返す。
  `tests/css-reading.test.js` の control case（前が 10px・後が 14px）があるので、
  `[0]` に戻すと赤くなる。
- **一般形**: カスケードは**最後が勝つ**。規則の間でも、規則の中でも。

### L-04 CSS のブロック主張が、隣のブロックに当たっていた

- **症状**: `.global-nav-brand` の border を主張していたが、一致していたのは
  同名を含む別ブロック。border を消しても緑。
- **どう見つかったか**: ミューテーション。
- **いま何が捕まえるか**: `scripts/lib/css.mjs` — セレクタを文字列として探すのを
  やめ、**規則として読みます**（`rulesOf` / `rulesNaming` / `fontSizePx`）。
  `tests/css-reading.test.js` が、この repo が実際に踏んだ 5 つの形を
  最小の stylesheet で固定し、さらに**手書きのトークナイザが 6 本目として
  生えたら赤くします**（コメントを剥がしてから探すので、それを禁じている
  説明文自体には当たりません——L-06）。
- **一般形**: L-02 と同じ根。**構造として読めるものを、文字列として探さない。**

### L-05 コメントを剥がすつもりが、本文の 93% を食べた

- **症状**: `/\/\*[\s\S]*?\*\//g` で block comment を剥がしたところ、
  `page.route('**/*')` の `/*` が開始と見なされ、**3,463 字中 3,208 字**が消えた。
  残り 255 字に対して、以降のすべての主張が通った。
- **どう見つかったか**: ミューテーション。何を壊しても緑なので、長さを印字した。
- **いま何が捕まえるか**: **人だけ**。行コメントだけを剥がす形にした。
- **一般形**: **剥がしたら長さを見る。** 前後の文字数を印字するだけで、この種の
  「入力が消えていた」は全部見えます。glob・正規表現・URL は `/*` を含みます。

### L-06 `doesNotMatch` が、それが駄目な理由を説明しているコメントに一致した

- **症状**: `assert.doesNotMatch(code, /route\.abort/)` が、
  「なぜ `route.abort` を使ってはいけないか」を書いた**コメント**に当たって赤くなった。
  主張は正しく、対象が違った。
- **どう見つかったか**: 赤くなったので。ただし逆向き（`match` がコメントに当たって
  **緑になる**）は見つかりません。
- **いま何が捕まえるか**: **人だけ**。コメントを剥がしてから測る形にした。
- **一般形**: **ソースを検索する主張は、コードに対して行う。** この repo は
  コメントが厚いので、`match` も `doesNotMatch` も、自分の説明文に当たります。

### L-07 CI の検査が、錨を下ろした 1 行の外を見ていなかった

- **症状**: `--with-deps (firefox|webkit)` に錨を下ろしたので、
  `--with-deps chromium firefox webkit` が素通りした。ファイル全体に広げたら、
  今度は**自分が書いた説明コメント**に当たった（L-06）。
- **どう見つかったか**: ミューテーション。
- **いま何が捕まえるか**: `tests/viewports.test.js` — コメントを剥がした
  `ciSteps` に対して測る。
- **一般形**: **錨は、守りたい性質ではなく、たまたま今そう書かれている形に当たります。**

### L-08 クラス名の部分一致が、entitled なコントロールを全部ロック扱いにした

- **症状**: 「class 名に lock を含む要素があるか」でロックを測った。錠前は
  **常に DOM にあり `hidden` になるだけ**なので、全件がロック扱い。
- **どう見つかったか**: entitled 側も `--locked` 側も同じ答えを返したので。
- **いま何が捕まえるか**: `scripts/check-gated-surfaces.mjs` — 製品自身の信号

  `tests/preview-grants.test.js` が、その 2 つを読んでいることを固定する。
- **一般形**: **製品が自分で持っている状態を読む。** 「それらしい class 名がある」は
  状態ではありません。

### L-17 L-01 が、L-01 を止めるために書いた file の中で再発した

- **症状**: この台帳のガードに「文書のテンプレートは lesson として数えない」という
  テストを書きました。`assert.ok(parseLessons(ledger).every((l) => l.id !== 'L-NN'))`。
  **パーサが何をしても通ります**——見出しの正規表現は `L-\d+` なので、
  `L-NN` は最初から一致しません。**空集合に対する不在の主張**（L-01）です。
- **どう見つかったか**: ミューテーション。fence の処理を `if (false)` に潰しても
  緑のままだったので。**7 つ壊したうち、これだけが緑でした。**
- **いま何が捕まえるか**: `tests/lessons.test.js` — 囮を**実在する番号**
  （`L-07`）で fence の中に置き、パース結果が `['L-07']` **と等しい**ことを主張する。
  `deepEqual` なので、数え過ぎも数え落としも赤くなります。
  fence を潰すと赤、文書側のテンプレートを fence から出しても赤。
- **一般形**: **「X が無い」は、「Y が有る」と同じ assert で書く。**
  `every(... !== x)` ではなく `deepEqual(all, [expected])`。
  そして——**教訓を書いた当人が、その教訓を、その場で繰り返します。**
  だからループの 3 手目は、書いた本人にも要ります。

### L-18 「欄が有るか」を見て、「何か書いてあるか」を見なかった

- **症状**: `npm run lessons` が必須 3 欄を `fields.has(name)` で検査していました。
  `- **症状**:` と書いて中身を空にすると、パーサは空文字列を格納し、
  `has()` は `true` を返します。**3 つの事実を 1 つも述べていない項目に対して、
  台帳は「well-formed」と報告します。** 内容の検査を受けていたのは
  ガード欄だけでした。
- **どう見つかったか**: **レビュー（Codex, P2）**。ミューテーションでは出ていません
  ——私が壊したのは `has()` の**結果**（欄を丸ごと消す）であって、
  **欄が有るまま中身が空**という状態を作っていなかったからです。
- **いま何が捕まえるか**: `tests/lessons.test.js` — 空欄 2 つを持つ項目に対して
  `problems` が**その 2 件と正確に一致する**ことを `deepEqual` で主張し、
  併せて**折り返した次の行から本文が始まる項目は通る**ことも主張します
  （空の検査をパース中に行うとこちらを誤って拒否します）。
  検査を `false` に潰しても `true` に潰しても赤くなります。
- **一般形**: **「有るか」と「何か言っているか」は別の主張です。** L-01 の同型
  ——あちらは空文字列に対して不在が通り、こちらは空文字列に対して存在が通りました。
  そして**ミューテーションにも死角があります**: 壊し方が 1 種類だと、
  その軸でしか測れません。**空・ゼロ件・空白だけ**は、消すのとは別に試してください。

### L-19 ミューテーションが、囮の**並び順**のせいで素通りした

- **症状**: 「`.copy` は `.copy-inner` に一致しない」を、
  `.copy-inner { 9px } / .copy:hover { 15px }` という stylesheet で主張しました。
  部分一致に壊すと**両方の規則が集まりますが、最後が勝つので答えは 15px のまま**。
  **アサーションの結果が、それが名指ししている性質に依存していませんでした。**
- **どう見つかったか**: ミューテーション。6 件中 1 件だけが緑で、
  ヘルパーの `namesClass` を `includes()` に潰しても誰も気づきませんでした。
- **いま何が捕まえるか**: `tests/css-reading.test.js` — 囮を**後ろに**置き
  （部分一致なら 9px が答えになる）、併せて
  `rulesNaming(...)` が `['.copy:hover']` **と一致する**ことを `deepEqual` で主張します。
- **一般形**: **囮は、混入したら答えが変わる位置に置く。** L-17 と同じ形
  ——あちらは空集合、こちらは「最後が勝つ」規則に隠れました。
  ミューテーションを 1 件だけ書いて緑なら、**まず囮の置き方を疑ってください。**

### L-20 「移しただけ」の統合が、4 つの挙動を静かに変えた

- **症状**: 5 本の手書き CSS トークナイザを 1 本に寄せたとき、**等価性の根拠として
  type-floor の baseline（33 シート・209 宣言）が完全一致することを示しました。**
  それでも 4 つの挙動が変わっていました:
  1. `font-size: 10px !important` が **px として数えられなくなった**
     （＝床をすり抜ける）
  2. `.copy span` が `.copy` を名指していると見なされ、`.copy { 10px }` の後に
     `.copy span { 16px }` があると**床検査が 16px で通る**
  3. 「`@` で始まる selector は飛ばす」という**私が足した安全策**が、
     `@import` は `;` で終わって次の規則の selector 塊に**畳み込まれる**ため、
     `browser-first-release-polish.css` の**最初の実規則を丸ごと捨てていた**
  4. `z-index` が `--overlay-z-index` の中に一致し、後者が前者の代わりに答える
- **どう見つかったか**: **レビュー（Codex, P2 × 4）**。私のミューテーション 8 件は
  1 件も捕まえていません。
- **いま何が捕まえるか**: `tests/css-reading.test.js` — 4 つそれぞれに最小の
  stylesheet を置き、4 方向に壊して赤を確認済み。
- **一般形**: **現在のデータでの等価性は、現在のデータが通らない経路の変更を
  証明しません。** 209 が一致したのは、4 つのどれも今の `src/styles/` に
  たまたま存在しなかったからです。統合するときは、
  **移した先の入力空間**（`!important`・子孫選択子・`@import`・`--` 接頭辞）を
  数え上げてください——移す前のコードが何を受け取っていたか、ではなく。
  そして **「念のため」で足した早期 return は、データを消します。**
  3 は元のコードには無く、私が足した 1 行です。

### L-22 マージがコード表を**コメントの中に**移し、検査はそれを読み続けた

- **症状**: `scripts/check-anatomy-interaction.mjs` の `SCENE_POINTS` に入って

  それでもテストは緑でした。`tests/beta-release.test.js` はスクリプトを
  **ファイル全体のテキストとして**読んで `'heart-anatomy': [` を探しており、
  **コメントの中の 4 つの名前を見つけて**「scope と tour は一致している」と
  答えていたからです。
- **どう見つかったか**: **実行して出力を読んだ**。`npm run verify:anatomy --
  --scene heart-anatomy` の note 行。テストからは 1 文字も出ていません。
- **いま何が捕まえるか**: `tests/beta-release.test.js` — 検索範囲を
  `const SCENE_POINTS = {` から閉じ括弧までに限定したうえで、**名前つき tour を
  持つ公開シーンの一覧を `deepEqual` で固定**しています。範囲を絞るだけでは
  足りません（tour が消えると「無い」に落ちて、`if (!names) continue` で
  静かに読み飛ばされる）。rows をコメントに戻す mutation で赤くなることを
  確認済みです——**範囲を絞っただけの版は緑のままでした**。
- **一般形**: **ソースをテキストとして読む検査は、コメントアウトされた自分の
  期待値を読みます。** 範囲をまず構文単位に絞る。そして
  **「無ければ読み飛ばす」は、消えたことを検出できない**——読み飛ばす対象は
  一覧で固定する。L-04（正規表現が別の規則に当たる）と L-01（不在が空集合に
  通る）が同時に出た形です。

### L-23 計測器が、測った名前をコメントにだけ書いて捨てていた

- **症状**: `scripts/measure-anatomy-points.mjs` は各点が**何に当たったか**を

  書いていました。`check-anatomy-interaction.mjs` は 3 番目の要素がある点しか
  構造名に対して検査しないので、**この loop が出したどの表も、貼った瞬間から
  検証されていません**。`SCENE_POINTS` の座標のみ 35 件はここから出ています
  ——F-123 そのものの供給源です。
- **どう見つかったか**: **レビュー（Codex, P1）**。PR #112 で、この loop を
  含む diff に対して。私はこの PR で F-123 を「次にやる作業」として読んで

- **いま何が捕まえるか**: `tests/beta-release.test.js` — 出力行が

  ソーステキストに対して主張します。裸の組＋コメントに戻す mutation で

  2 つの道具の間にある「人が読み替える一手」が、ずれの入り口です。

## B. ガードが、存在しないか、届いていなかった

### L-09 編集スクリプトが途中で assert し、何も書かずに終了した

- **症状**: テストを追加する編集スクリプトが、途中の整合性 assert で落ちて

- **いま何が捕まえるか**: **人だけ**。
- **一般形**: **書いたつもりのガードは、壊して赤を見るまで存在していません。**
  これがループの 3 手目が要である理由です。編集スクリプトは
  「書いた」ではなく「書いたものを読み直して」確認してください。

- **症状**: `--points` に 21 点を渡して掃いたところ、返ってきたのは

- **いま何が捕まえるか**: **人だけ**——ただし原因は消しました。

### L-25 推論で選んだ許容値が、無視するはずのものを飲み込んだ

- **症状**: 再構図の「読者がカメラを触ったか」判定を、厳密比較から
  `max(1e-3, distance * 0.005)` に緩めました。根拠はコメントに書いたとおり
  **「意図的な zoom の最小刻みよりはるかに小さい」**——これは測っていません。
  実際には、ホイール 1 刻みは damping 越しに徐々に効くので **zoom の開始直後は
  まだ 0.5% 以内**にいます。そこで band が変わると watcher が
  「触られていない」と判定し、**読者の zoom ごとカメラを吸着**しました。
  公開中の `brain-anatomy` で、390x844 の zoom が被写体を **20px** 動かします
  （anchor が効いていれば 0px）。
- **どう見つかったか**: `verify:anatomy` を公開シーンで回したから。
  **テスト 2583 件は 1 件も赤くなっていません。** 自分が原因かどうかは、
  `origin/main` を git worktree に出して同じ drive を回して確定させました
  （main は `exit=0`）。犯人の特定は 2 変更を 1 つずつ戻す二分探索です。
- **いま何が捕まえるか**: `scripts/check-anatomy-interaction.mjs` の zoom 4 件
  ——**ちょうど 0px** を期待します。修正は撤回し、F-133 を再オープンしました。
- **一般形**: **閾値は測ってから書く。** 「A は B よりずっと小さい」と
  コメントに書けてしまうことと、実際にそうであることは別です。
  そして今回は**そもそも閾値が存在しませんでした**——damping の残差と
  zoom の立ち上がりは同じ量で、分離できません。
  **分けられない 2 つを閾値で分けようとしていないか**を先に疑ってください。
  L-15（確かめる前に主張した）の、数値版です。

### L-26 計測器と検査器が、同じシーンを別の瞬間に測っていた

- **症状**: `points:anatomy` が掃引で出した 4 点を `SCENE_POINTS` に貼り、
  `verify:anatomy` を回すと **掃引が直前に確認した点で「何にも当たらない」**。
  同じシーン、同じ viewport（1280x800）、同じ日。2 つの計器が矛盾しました。
  原因は**測る瞬間**です——掃引はシーンが開いた直後で測り、drive は step 0 の
  framing 検査（表示のリセットを含む）を経たあとで tour を実行します。
  `lung-anatomy` は開いた直後 0.22..0.50、落ち着いて 0.20..0.52 と**構図が
  違う**ので（F-133）、掃引の座標は drive の frame では別の場所を指しました。
- **どう見つかったか**: 再計測した tour が、再計測したのに落ちたから。
  `brain` と `liver` では 2 つの構図が一致していたので**露見しませんでした**
  ——つまりこの不一致は、ずれるシーンが来るまで何年でも隠れられます。
  なお途中で main と比較しようとして 10 分無駄にしています：**比べようとした
  「開始構図 vs reset 構図」の検査自体がこちらの追加**で、main にはその行が
  存在しませんでした（比較にならない比較）。
- **いま何が捕まえるか**: **人だけ。** `SCENE_POINTS` の lung・knee・shoulder の
  項に、この scene は drive で測ること、掃引を使ってはいけないことを書いています。
  機械的には、2 つの計器が同じ瞬間を見ているかを主張する検査が
  要りますが、まだありません。
  **2026-09-16 追記: 膝と肩でも同じことが起きました。** 掃引は膝の
  (0.365, 0.37) を "Patella" と呼び、drive は同じ点で "Quadriceps tendon" と
  答えます——**丸ごと 1 行ぶんずれて**、下まで同じだけずれています。
  肩は掃引の 3 点のうち 2 点が drive では何にも当たりません。
  肺 1 件のときは「ずれるシーンが来るまで隠れられる」と書きましたが、
  **3 件目です。もう例外ではありません。**
- **一般形**: **「同じものを測っている 2 つの計器」は、同じ*時点*を見ている
  とは限りません。** 片方が定常状態、片方が初期状態を測っていると、
  両者が一致するケースでは何年でも気づけず、ずれるケースで初めて出ます。
  値を突き合わせる前に、**いつ測ったのかを突き合わせてください。**
  L-25 が「閾値は測ってから」なら、これは「**測定は時点まで含めて測定**」です。
