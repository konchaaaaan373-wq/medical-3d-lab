## 3. `higher-brain-function` — 正常機能の解説と、機能障害シミュレーションを分けるか

### 3.1 いまのモデルの作り

モデルは 1 つです。各課題（復唱・聴覚的理解・呼称・読字・書字・行為・注意・記憶の形成・遂行機能）を
「名前の付いた構造を順に通る経路」として宣言し、**経路が通るか**を解きます。

- **正常機能の解説** = どの課題がどの構造・どの線維を通るかを、経路として見せること
- **機能障害シミュレーション** = 構造を選んで壊し、どの課題が残るかを解かせること

2 つは同じ解から出ており、根拠資料（[`../model-evidence/higher-brain-function.md`](../model-evidence/higher-brain-function.md)）も
共通です。**ただし主張の強さが違います。**

| | 正常機能の解説 | 機能障害シミュレーション |
| --- | --- | --- |
| 主張 | 「この課題はこの経路を通る」 | 「ここを失うとこの症候になる」 |
| 根拠の種類 | 古典的な離断モデルの教科書的記述 | 同じ記述から**導いた**帰結 |
| 誤読の危険 | 局在の単純化 | **病巣同定の道具として読まれる**こと。連絡に左右が無いため視床皮質離断が実際より重く出る（F-165）。Gerstmann は根拠が最も弱い |
| 人のレビューが無いまま出す重さ | 中 | 高 |

### 3.2 実装者の推奨

**分けて、正常を先に。** 具体的には:

1. `higher-brain-function` に「病変を置く操作を出さない view」を足し、それを既定にする
   （`cardiac-output` が入門教材を既定、詳しいモデルを `?view=detail` にしたのと同じ構造）
2. 公開判断は view ごとに取る。まず正常の view だけを、ADR 2026-09-22 の足場
   （学習者向け・alpha バッジ・レビュー未完了の表示）で開く
3. 病変シミュレーションは、F-165（連絡の側性）を直し、**人の臨床レビュー**を受けてから

**この PR は 1〜3 のどれも実装していません。** view を分ける実装と、view 単位の公開判定は
設計判断を伴うので、所有者が方針を決めてから着手します（F-286）。

| --- | --- |
| H-A | 上の「分けて、正常を先に」で進めてよいですか |
| H-B | 正常の view を、臨床レビュー無し（`cardiac-output` と同じ足場）で公開してよいですか。それとも正常の view にも人のレビューを要求しますか |
| H-C | 公開中の脳解剖・MRI アトラスで構造を選んだとき、「この部位が関わる高次脳機能」を表示しますか（F-166。仕組みは実装済みで、機能モデルが閉じている間は出ません） |

### 4.3 モデルの既知の限界（モデルカード §10。**公開判断記録の `unverified` に写す項目**）

1. 脳梁に膨大部が無い（後方の脳梁病変が脳梁全体として描かれる）
2. 中心前回に体部位局在が無い（口と手が一緒に失われる）
3. 読字と視覚性呼称が 1 経路（純粋失読で物品呼称が保たれる解離を示せない）
4. 超皮質性運動失語で呼称が保たれる（人では様々に障害される）
5. 単独の呼称障害を生む部位が無い
6. 中前頭回が 1 メッシュ（運動前野と背外側前頭前野が同じ構造になる）
7. 連絡に左右が無い（視床皮質離断が両側で切れ、実際より重く出る。F-165）
8. **線維束 54 本のメッシュを解剖学者が見ていない**（F-159）

## 5. 公開済み URL への影響

| URL | いま | マージ後 |
| --- | --- | --- |
| `#/brain-anatomy`（静的ページ `/s/brain-anatomy/`） | 公開 | 公開（変わらず） |

| `#/models`・`#/anatomy`・`#/about`・`#/trust`・規約類 | 公開 | 公開（内容は公開範囲に追随） |
| `#/mri-atlas`・`#/functions` | なし | 新規 |

検索エンジンに載っている 4 ページが 404 になります。リダイレクトは設定していません——
非公開にしたモデルの URL を公開中の別モデルへ転送すると、「心臓を探して来た人に脳を見せる」
ことになるためです。サイトマップからは自動的に外れます。**転送したい場合は指示してください**（F-288）。
