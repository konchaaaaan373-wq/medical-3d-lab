# ADR 2026-09-22 — 公開βを「解剖だけ」から広げ、`cardiac-output` を公開する

Status: Accepted（実装済み）
所有: 公開範囲の判断。実装は [`../../src/catalog/release.js`](../../src/catalog/release.js)、
現在の状態は [`../beta-release.md`](../beta-release.md)。
[ADR 2026-09-08](adr-2026-09-08-anatomy-only-beta.md) の **決定 1 を部分的に置き換えます**
（代用の禁止は残し、「解剖だけ」の部分を外します）。

## Context

2026-09-08 の ADR は、公開βを解剖層だけに絞りました。その理由は正しく、いまも
有効です——当時のルール（`organ ∈ {brain, heart}` かつ非 prototype）では、
**心臓の解剖モデルが無いことが心不全・低心拍出・心筋虚血を公開する理由に
なっていました**。解剖の代わりに病態を出す、という代用です。

2026-09-22、`cardiac-output`（循環充満・体血管抵抗・収縮力・心拍数を 1 つずつ
動かし、同じ 1 拍から 3D・数値・PV ループ・波形・字幕のすべてを導くシーン）が
`alpha` で登録されました。ゲートは `mechanismLevel !== 'none'` を理由に
これを閉じます。**それは設計どおりの動作で、不具合ではありません。**

リポジトリ所有者は、この 1 本を公開する判断を出しました。

## Decision

**βは「解剖だけ」をやめます。解剖の候補一覧に加えて、機序を解くシーンの候補
一覧を持ち、そこに載せた 1 本ずつを、それぞれの公開判断記録とともに開きます。**

1. **代用の禁止は残ります。** 病態シーンを解剖シーンの「代わりに」公開する
   ことは、いまも禁止です。`cardiac-output` が開くのは `heart-anatomy` が
   開いた**あと**であって、その代わりではありません。
2. **一覧は 2 本、主張のルールは共有しません。**
   `BETA_ANATOMY_CANDIDATES` は従来のルールのまま（構造の主張のみ・
   `anatomyClaimProblems` は 1 行も変えていません）。
   `BETA_MECHANISM_CANDIDATES` が新しい方で、機序の主張を許します。
   **それ以外のゲートは 1 つも緩めていません**——患者個別モデル不可、
   clinical 用途の宣言不可、asset release gate、レビューが stale でない、
   asset hash と scene revision に結びついた公開判断記録。
3. **患者向けの機序シーンは、いまも現行の臨床レビューを要求します。**
   次リリースのチャネルが持っていたこの規則に穴は開けません。
   `intendedUses` に `patient-explanation` を含む、または患者ビューを持つ
   シーンは、現行レビューが無ければ閉じたままです。
   **βが新たに開けるのは「学習者に向けた機序」であって「患者に向けた機序」
   ではありません。**
4. **広いルールではなく、名前の一覧です。** 「記録が揃っている機序シーンは
   すべて開く」は、1 つの判断で十数本を開けてしまいます。判断は 1 本に
   ついて出されたので、一覧も 1 本です。

## What this knowingly accepts

**`cardiac-output` に臨床レビューはありません。** 登録簿は `pending` です。
所有者はそれを承知のうえで公開を決めました。これは記録されるべき事実であって、
ページが開いていることから推測されるべきものではありません。

受け入れているものを明示します。

- **臨床家も生理学者も、このモデルを読んでいません。** 基準条件・プリセット・
  介入の大きさ・文言のいずれについても、外部の専門的判断はありません
- **external validation はありません。** `mechanismLevel: mechanistic` であって
  `literature-calibrated` でも `externally-validated` でもない。基準条件は
  「教科書の代表値に着地するよう選んだ較正」です
- **反射性調節がありません。** 抵抗を上げても心拍数は戻りません。圧受容器反射は
  モデルに存在しないので、ここでの「1 つだけ変える」は生体の応答ではなく
  モデルの応答です

受け入れていないものも明示します——これらが担保だからです。

- 画面には `alpha` バッジと `医学レビュー：未完了` が出ます。消しません
- profile が diagnosis / treatment-selection / dose-selection / prognosis を
  禁止用途として宣言し、scope panel が数値と同じ画面でそれを述べます
- 掃引域の外は**丸めずに拒否**し、収束しなかった拍は `metrics: null` を返します
  ——読める数値が存在しません
- 介入は用量ではなく向きです。ドブタミンは出典どおり心拍数を据え置きます

## Consequences

- `verify:site` の公開件数が 1 増えます。**件数はここに書きません**
  （CLAUDE.md の規則。数えたいときは `npm run verify:site`）
- production ビルドに `cardiac-output` の chunk が入ります。バンドル予算は
  `npm run budget` が持ちます
- `tests/beta-release.test.js` は「βは解剖だけ」を固定していました。いまは
  「解剖の一覧は解剖だけ」「機序の一覧は名指しした 1 本だけ」「患者向けの
  機序は現行レビューを要する」を固定します
- 次にこの一覧へ 1 本足すときは、**その 1 本についての判断**と、その記録が
  要ります。この ADR は一般的な許可ではありません
