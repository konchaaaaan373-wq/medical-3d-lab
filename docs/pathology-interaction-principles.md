# 病態モデルの操作原則

病態モデル（時間変化・因果・複数変数の連動を扱うシーン）の**操作方法**についての
恒久原則です。この文書が正本で、CLAUDE.md は参照だけを持ちます。

- なぜ 3D を使うか・何を作らないか → [`product-principles.md`](product-principles.md)
- 表示・定型視点・リセット境界 → [`architecture/spatial-inspection.md`](architecture/spatial-inspection.md)
- キーボード・フォーカス・コントラスト → [`accessibility.md`](accessibility.md)
- 個々のモデルで何を採用したか（例: 心拍出量の XY パッド）→ そのモデルの
  [`model-cards/`](model-cards/)。**この文書には個別の採否を書きません**

判断基準は 1 つです。

> **難しい医学を、難しい操作で扱わせない。しかし、簡単な操作のために医学を別物にしない。**

## 原則

1. **操作方法は病態モデルの中核機能です。** 完成後も継続的に工夫・改善します。
   「シーンができたから操作は付属品」とは扱いません。

2. **操作している間は、操作 UI・アニメーション・主要な結果を同じ画面で確認できる
   ようにします。** 操作するためにスクロールして心臓へ戻る、パネルを開いたら観察対象が
   消える、という構造にしません。
   - 「常に見える」は自動再生を強制する意味ではありません。一時停止や動きを抑える設定でも、
     観察対象は画面に残ります
   - 出典や限界を読む画面と、モデルを操作する画面は別です。前者を開いている間まで
     同時可視を求めません

3. **重ならないだけでは足りません。** 操作中に形態や動きの変化を読み取れる大きさ・視点・
   コントラストを確保します。判断の対象は、周辺の図（例: 循環ループの外周）ではなく、
   変化が起きている構造（例: 左室）です。

4. **操作性はゲームと同じくらい真剣に設計します。** ただしそれは、装飾・得点化・派手な演出・
   複雑なジェスチャーを増やすことではありません。反応の速さ、つかんだときに値が跳ばないこと、
   指を離したあとの予測可能さ、中断からの回復を詰めることです。

5. **操作性は、入力の快適さだけでなく、医学的因果関係の追いやすさで評価します。**
   何を変えたらどこが動き、その結果どの数値がどちらへ動いたかを、利用者が追えるか。

6. **利用者が変更した入力・固定した入力・モデルが計算した結果を区別できるようにします。**
   「変えたもの」と「変わったもの」を同じ見た目・同じ列に並べません。

7. **操作や演出の都合で、医学的な意味・数式・適用範囲を変えません。** 計算していない現象を
   計算結果のように見せません。見えにくいときに動かすのは視点・色・不透明度・時間の
   見せ方であって、臨床パラメータではありません（CLAUDE.md「Never alter physiology for
   visual impact」）。

8. **自由な探索と、一つの条件だけを確かめる操作を両立させます。** 分かりにくさを理由に
   自由度を一律に撤去しません。逆に、自由度のために「一つだけ変える」を難しくもしません。

9. **ドラッグ・長押し・二本指・同時押しだけを唯一の操作方法にしません。** タップだけで、
   またキーボードだけで、同じ入力に到達できるようにします（WCAG 2.5.7 Dragging Movements）。

10. **実機・初見の利用者・挙動テストで評価し、実装 → 評価 → 改善を続けます。**
    自動テストの成功を、医学的妥当性や教育効果の証明と呼びません。エミュレーションを
    実機確認と、少人数の操作確認を教育効果の証明と呼びません。

11. **XY パッドは候補の一つです。** 病態と学習目的に合った操作方法を選びます。共通化するのは
    この原則と下の入力契約であって、全画面の形ではありません。

12. 判断に迷ったら、冒頭の基準に戻ります。

## 入力契約（全病態モデル共通）

操作部品の形は自由ですが、モデルへの入り方は次を守ります。

| 項目 | 契約 |
| --- | --- |
| 変更の単位 | 操作は「どの入力を、どの値へ」を明示した変更として送る。全パラメータの一括上書きをしない |
| 一軸操作 | 指定した 1 入力だけを変える。他の独立入力は厳密に保持する |
| 複数入力の操作 | 指定した入力を**一まとまりの 1 変更**として反映する（1 回の解・1 回の Undo） |
| 従属変数 | モデルが計算する量の変化は「保持」の対象ではない。保持するのは独立入力だけ |
| 無効な入力 | コミットしない。最後に有効だった状態を保ち、受け付けなかった理由を小さく示す。別の入力を黙って動かして有効域へ押し込まない |
| Undo | 利用者の 1 操作（1 回のドラッグ・1 回の押下）を 1 回で戻す。pointermove ごとに履歴を増やさない。戻すのが入力だけか内部状態・時刻までかを、モデルごとに明記する |
| 開始時に戻す | 現在の実験の開始状態へ。視点のリセットとは別の操作 |
| 新しい開始状態 | それまでの実験を置き換えることが分かる操作にする |
| 比較元 | 実験の開始状態に固定し、操作のたびに更新しない |
| 表示 | 3D・数値・グラフ・操作部品の表示は、同じ適用済み入力と、それに対応する計算状態から作る。未適用の値を適用済みのように見せない |
| 中断 | pointercancel・capture 喪失・背景移行では、最後に適用した有効値を保ち、未送信の入力を捨てる。明示的な Undo とは区別する |
| 配置 | 最初の入力・差分の出現・桁数の変化で、操作中の部品の位置と大きさを変えない |

## 操作面に描かないもの

- 良否・重症度・正解を示す配色や領域（「中央が良好」「右上が改善」など）。根拠のない
  「正常」「心不全」「ショック」の領域
- 相対変化量だけによる重要度・重症度・良否の判定
- 右上へ動かす、数値を最大にする、正常域へ戻すことを正解にするゲーム化
- 入力値の変化を、測定された生体応答のように表示すること
- 「この操作なら必ず〜が増える」のような、計算結果を超える固定の説明

## 評価の記録

新しい操作方法を採用したら、そのモデルのモデルカードに次を書きます。

- 何を採用し、何を候補として残したか
- 各入力の意味・単位・範囲・座標との対応、組み合わせの数値的な確認範囲
- 入力と 3D 表現の対応（何の模式表現か）
- 実装済み／ブラウザ確認済み／実機確認済み／医学レビュー済みの区別と、未確認事項
- 初見の利用者に確認してもらう課題（手順）と、その結果または未実施であること
